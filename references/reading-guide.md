# PaperMentor 阅读与故障处理指南

---

# 执行工作流

## 1. 任务识别

将请求识别为 `read`、`compare`、`ask`、`group_meeting` 或 `flashcards`。记录论文数量、阅读深度、关注点和输出格式。用户未指定时，单篇默认精读，多篇默认文献矩阵，追问默认简洁回答并附证据。

## 2. 输入检查

每篇论文使用稳定的 `paper_id`，不得仅依赖相似文件名。检查文件可读性、加密状态、页数和可提取文本。相同文件可复用同一输出目录中的解析结果，但文件内容变化后必须重新解析。

## 3. 确定性解析

依次执行 `scripts/paper_tools.py` 的 `inspect`、`extract`、`sectionize` 和 `context` 子命令，具体命令见 `SKILL.md`。脚本只负责文本、页码、章节和格式，不负责语义总结。解析状态异常时读取故障处理规范。

## 4. 语义阅读

按任务读取相应 reference。先确定研究问题和论文结构，再阅读方法和实验。关键结论必须同时保存论断、页码、章节和短原文。长论文分批阅读，保留未读章节列表，不把未读内容当作不存在。

## 5. 可选并行

宿主支持子 Agent 且任务符合并行条件时，按子 Agent 编排规范分派。串行与并行模式必须遵循同一字段和证据要求。子 Agent 的结果只是候选内容，不是最终事实。

## 6. 合并与校验

主 Agent 合并内容并去重。不同结果冲突时回到原文核查，不采用多数表决。先执行证据校验，再执行结构校验；失败时只修复受影响字段。

## 7. 输出与记录

按模板输出，说明论文覆盖范围、解析限制和不确定项。测试任务还应记录实际配置、失败案例和修复结果，不得把目标指标写成实测结果。

# 单篇论文阅读规范

## 速读

优先阅读摘要、引言末尾、结论和主要实验表格。输出一句话问题定义、核心方法、最关键结果、作者明确局限和三条证据。速读不代表已覆盖全文，应注明未深入阅读的章节。

## 精读

### 研究问题

说明研究对象、现有方法缺口、论文目标和适用边界。引言未明确支持的内容不得写成论文动机。

### 方法

按输入、关键步骤、输出和训练或推理过程拆解。区分方法实际组成与作者对优势的声称。公式无法可靠解析时，结合正文解释并标记公式文本不确定，不自行补全符号含义。

### 实验

分别提取数据集或实验对象、基线、指标、实验设置、主要结果和消融实验。数值必须保留对应表格或正文证据。不同设置下的数值不得拼接成同一比较。

### 创新点

优先写成“作者声称的创新”，随后给出支持该创新的方法或实验证据。常见组件的简单改名不能自动判定为创新。

### 局限与复现

先列作者明确局限，再列基于证据的分析。分析必须标记为 `agent_inference`。代码是否公开、超参数是否完整、数据是否可用等无法确认时写“论文未说明”，不要根据经验猜测。

## 组会阅读

在精读结果上组织汇报，不重新生成另一套事实。建议顺序为研究背景、问题、方法、关键实验、证据评价和讨论问题。讨论问题应帮助听众判断方法成立条件，而非只复述论文内容。

## 复习卡片

每张卡片只考查一个问题，答案保持简洁并附证据。至少覆盖研究问题、方法关键步骤、主要实验和一个局限，不制作论文无法回答的伪事实卡片。

# 多篇论文对比规范

## 前置条件

每篇论文必须独立完成结构化和证据校验，并始终保留 `paper_id`。某篇解析不完整时，在矩阵对应单元格标记未知，不得用其他论文内容补齐。

## 统一维度

至少比较研究问题、方法类别、关键机制、数据集或实验对象、指标、主要结果、作者结论、明确局限和复现信息。可根据研究方向增加维度，但所有论文使用相同字段。

## 可比性

每个实验比较标记为：

- `comparable`：任务、数据、指标和关键设置一致。
- `partially_comparable`：部分条件一致，差异已明确披露。
- `not_comparable`：任务、数据集、指标或设置存在根本差异。

`not_comparable` 的数值不得用于优劣排名。缺少设置信息时最多标记为 `partially_comparable` 或未知，并解释原因。

## 综合分析

研究演进必须由论文时间、方法引用或明确技术关系支持。共识需要至少两篇论文证据，分歧需要分别列出各方证据。研究空白属于分析建议，标记为 `agent_inference`，不能写成领域已经证明的事实。

## 输出检查

逐单元格核对论文来源，确保方法、实验数值、引用和局限没有串线。矩阵之后列出关键证据索引，使读者能够回到原论文验证综合结论。

# 论文问答规则

## 检索范围

只使用当前对话明确提供的论文及已解析上下文。先定位相关章节和页码，再组织答案。不得用其他论文、模型记忆或常识代替原文证据。

## 回答方式

事实问题先给简洁答案，再列页码和短原文。需要跨章节综合时说明综合关系，并分别提供证据。数字、比较级、否定和适用范围必须逐项核对。

## 不可回答问题

论文未涉及、已读范围不足或解析质量不足时，分别说明：

- “论文没有提供该信息”：已可靠覆盖相关内容，可以确认未说明。
- “当前已读内容不足以回答”：仍有相关章节未读。
- “该部分解析质量不足，无法可靠回答”：文本或公式解析存在异常。

不得把这三种情况都写成确定否定。

## 追问处理

追问沿用原论文的 `paper_id` 和证据体系。用户要求比较其他工作但未提供对应论文时，只能给出一般分析建议，并明确该建议不属于原论文结论。

# 输出字段说明

## 基本信息

`paper_id` 是内部稳定标识；`title` 和 `authors` 只填写可确认内容；`reading_depth` 为 `quick`、`full` 或 `group_meeting`；`coverage` 记录实际阅读范围与未覆盖章节。

## 核心字段

- `research_question`：研究对象、现有缺口和论文目标。
- `summary`：基于全文已读范围的简短概括，不只是摘要翻译。
- `methods`：方法名称、步骤、输入输出及对应证据。
- `experiments`：数据集、基线、指标、设置、结果和消融实验。
- `contributions`：作者声称的贡献及其支持证据。
- `limitations`：作者明确局限或明确标记的分析推断。
- `reproduction`：代码、数据、超参数和复现风险；未知字段保持未知。
- `claims`：供统一证据校验的关键论断列表。

## 证据与状态

每条关键论断包含 `statement`、`statement_type`、`section` 和 `evidence`。`statement_type` 只能使用规定枚举。无法确认的内容写入 `uncertainties`，解析问题写入 `warnings`，两者不能隐藏在完整笔记之后。

## 多篇输出

每篇论文保留独立卡片，对比矩阵的每个事实单元格保留来源 ID。综合观点需要列出来源集合；不可比结果必须包含原因。

# 故障与降级处理

## 加密或不可读 PDF

记录 `encrypted` 或 `unreadable` 状态，请用户提供可读取版本。不得根据文件名或摘要猜测全文并生成完整笔记。

## 扫描件或正文过少

可提取字符过少时标记 `insufficient_text`。宿主具备可靠 PDF 视觉读取能力时，可尝试按页阅读并明确说明页码依据；否则建议提供文本版或 OCR 版本。未成功识别的页面不得当作已阅读。

## 双栏错序

检查标题、句子和段落连续性。能依据文本块坐标可靠重排时重排，否则按较小上下文阅读并保留警告。实验数字必须与同段上下文核对。

## 公式和表格异常

公式符号不完整时，以正文定义为辅助并标记不确定性，不自行补全公式。跨页表格无法确认行列关系时，只提取能够确认的数据，避免强行生成完整表格。

## 章节识别失败

退回页级上下文，按摘要、方法、实验和结论的关键词定位。无法确认章节名时使用 `Unknown` 或页码范围，不虚构章节结构。

## 脚本依赖缺失

说明缺少 PDF 解析依赖。宿主若支持直接读取 PDF，可改用宿主能力并保留页码；否则提供依赖安装建议。证据与结构校验脚本不可用时，不得声称已经自动校验。

## 子 Agent 失败

保留其他有效结果，由主 Agent 补读失败范围。一次无效返回后先修正任务契约，不反复进行相同调用。最终输出不得因并行失败而省略证据校验。
